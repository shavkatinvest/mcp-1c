# Write-инструменты (буxгалтерские операции)

По умолчанию mcp-1c работает в read-only режиме — write-инструменты (`create_document`,
`post_document`, `unpost_document`, `update_document`, `create_catalog_item`,
`update_catalog_item`, `set_deletion_mark`) вообще не регистрируются на MCP-сервере и
AI-ассистент их не видит. Этот документ описывает, как безопасно включить их.

## Как это работает

- **create_document** создаёт только черновик документа (`Записать(РежимЗаписиДокумента.Запись)`).
  Провести документ этим вызовом невозможно — параметра "провести" в запросе нет вообще.
- **post_document** / **unpost_document** проводят или отменяют проведение уже созданного
  документа по его `ref`.
- **update_document** / **update_catalog_item** изменяют реквизиты/табличные части уже
  существующего объекта; named-табличная часть заменяется целиком. `update_document` никогда
  не проводит/распроводит документ.
- **create_catalog_item** создаёт элемент или группу справочника.
- **set_deletion_mark** ставит/снимает пометку удаления (документ или справочник) —
  физического удаления в этом расширении нет и не будет.
- **find_ref** / **get_catalog_item** / **get_document** — read-only, всегда доступны
  независимо от режима записи. `find_ref` — единственный способ получить GUID
  ссылочного реквизита для остальных write-инструментов; не изобретайте GUID вручную.

Каждая write-операция логируется в журнал регистрации 1С с префиксом `MCP:` —
`MCP: СоздатьДокумент`, `MCP: ПровестиДокумент`, `MCP: РаспровестиДокумент`,
`MCP: ИзменитьДокумент`, `MCP: СоздатьЭлементСправочника`, `MCP: ИзменитьЭлементСправочника`,
`MCP: ПометкаУдаления`. Эти записи можно прочитать через `get_event_log` (`event` содержит
соответствующее имя события) — подтверждено 1:1 соответствие на реальной тестовой базе.

### Blacklist типов документов/справочников (`--write-type-blacklist`)

Независимо от прав `mcp_writer` в 1С, Go-слой отказывается выполнять любую write-операцию
для типов, совпадающих с glob-паттернами из `--write-type-blacklist` (по умолчанию
`dibank_*,дибанк_*` — банковские платёжные документы). Это вторая, независимая от 1C-ролей
защита: даже случайно выданные полные права не позволят AI-ассистенту тронуть платёжку.
Пустая строка (`--write-type-blacklist=""`) отключает проверку целиком — осознанный шаг для
тех, кто понимает риск.

## Шаг 1. Создать отдельного 1С-пользователя для записи

**Никогда не используйте пользователя с "Полными правами".** Создайте отдельного
пользователя (например `mcp_writer`) и назначьте ему **только** роль `MCP_РольЗаписи`
(поставляется расширением вместе с `MCP_ОсновнаяРоль`).

`MCP_РольЗаписи` из коробки даёт доступ только к write-эндпоинтам HTTP-сервиса
(`/document`, `/document/post`, `/document/unpost`, `/document/{type}/{ref}`) — права
на конкретные виды документов (Чтение/Добавление/Изменение/Проведение/ОтменаПроведения)
и связанные регистры **нужно добавить отдельно**, под каждый вид документа, который вы
хотите разрешить создавать через MCP. Это намеренно: чем меньше видов документов в
списке — тем меньше поверхность для ошибок AI-ассистента.

Как добавить права на вид документа (в Конфигураторе, для расширения):
1. Откройте расширение `MCP_HTTPService` → `Роли` → `MCP_РольЗаписи`.
2. В редакторе прав найдите нужный документ (например `РеализацияТоваровУслуг`) и
   поставьте галочки: `Чтение`, `Добавление`, `Изменение`, `Проведение`
   (и `ОтменаПроведения`, если нужен `unpost_document`).
3. Если при проведении 1С сообщает о нехватке прав на регистр (например
   `РегистрНакопления.ТоварыНаСкладах`) — добавьте `Чтение`/`Изменение` на этот регистр
   тем же способом. Точный список регистров зависит от вашей конфигурации и обычно
   выясняется опытным путём при первом тестовом проведении (см. ниже).
4. **RLS (ограничения доступа на уровне записей).** В конфигурациях с несколькими
   организациями (типично для БСП-based "Бухгалтерия") базовых прав (`Read`/`Insert`/
   `Update`/`Posting`) может быть недостаточно — платформа вернёт `Нарушение прав доступа!`
   даже при явно выставленных галочках, если для объекта настроены RLS-шаблоны. В этом
   случае откройте существующую рабочую роль (например "Бухгалтер") в редакторе прав и
   скопируйте её RLS-ограничения (столбец с иконкой замка́) для нужного вида документа —
   либо явно назначьте `mcp_writer` доступ к нужным организациям через тот же механизм,
   что используется для обычных пользователей. Это подтверждено на реальной тестовой базе:
   `Document.ОперацияБух` с правами `Read/Insert/Update/Posting/UndoPosting` без RLS-настройки
   давал `Нарушение прав доступа!` при `СоздатьДокумент()`; с временной ролью "Полные права"
   ошибка исчезала, что и указывает на RLS, а не на баг в BSL-коде write-эндпоинта.
5. **Пользователь должен существовать и в Предприятии, не только в Конфигураторе.** В
   БСП-based конфигурациях ("Бухгалтерия для Узбекистана" и подобные) система прав
   (Группы доступа) читает `Справочник.Пользователи`, а не только список
   "Пользователи информационной базы" из Конфигуратора. Пользователь, созданный ТОЛЬКО
   через Конфигуратор (`ИБ-пользователь`), но не связанный со `Справочник.Пользователи`,
   будет иметь назначенную роль (`РольДоступна("MCP_РольЗаписи")` = Истина), но
   `ПравоДоступа()` на конкретные объекты всё равно будет возвращать `Ложь`, и любой запрос
   к данным упадёт с `Недостаточно прав для работы с таблицей "..."` — даже если в Rights.xml
   роли явно прописаны `Read`/`Insert`/`Update` для этого объекта. Подтверждено runtime-
   диагностикой (`РольДоступна`/`ПравоДоступа` возвращали `Да`/`Нет` соответственно) на
   реальной тестовой базе. **Исправление:** создайте пользователя через
   `Предприятие → Администрирование → Настройки пользователей и прав → Пользователи →
   Создать`, указав существующего ИБ-пользователя как логин (или создайте нового прямо
   там) — это создаёт связанную запись `Справочник.Пользователи` автоматически.
6. Обновите базу данных (F7) и переустановите расширение (`mcp-1c --install ...`), если
   меняли исходники расширения, а не только права через интерфейс Конфигуратора.

## Шаг 2. Запустить сервер с write-флагами

```bash
mcp-1c --base http://localhost/base/hs/mcp-1c \
  --user mcp_reader --password <пароль читателя> \
  --enable-writes \
  --write-user mcp_writer --write-password <пароль писателя>
```

Или через переменные окружения:

```
MCP_1C_ENABLE_WRITES=true
MCP_1C_WRITE_USER=mcp_writer
MCP_1C_WRITE_PASSWORD=<пароль>
```

`--enable-writes` без `--write-user`/`--write-password` — ошибка запуска (сервер не
стартует), а не тихий откат на read-only пользователя. Это исключает ситуацию, когда
write-инструменты случайно работают под менее защищённой учёткой.

Read-only инструменты (`--user`/`--password`) и write-инструменты (`--write-user`/
`--write-password`) **всегда используют разные HTTP-соединения** с разными учётными
данными — даже если по ошибке `mcp_reader` получит лишние права, write-инструменты
всё равно обратятся только к явно указанному `mcp_writer`.

## Шаг 3. Проверить на тестовой базе, не на боевой

1. Сделайте копию базы (`Администрирование → Копирование информационной базы` или
   `/DumpIB` + `/RestoreIB`).
2. Установите расширение и создайте `mcp_writer` в этой копии.
3. Запустите `mcp-1c` с `--enable-writes`, указывая на копию.
4. Полный цикл вручную через MCP-клиент: `create_document` → `get_document` (проверить
   `posted: false`) → `post_document` → `get_document` (проверить `posted: true`) →
   `get_event_log` (проверить записи `MCP:`) → откройте документ в тонком/толстом
   клиенте 1С и убедитесь, что движения корректны.
5. Только после того как этот цикл пройден несколько раз и результат проверен вручную —
   переходите к боевой базе, и даже тогда сначала подержите `--enable-writes` выключенным
   какое-то время в проде, прежде чем включать.

## Безопасность

- Никакого произвольного выполнения кода (`execute_query` — только `SELECT`, write-tools —
  только конкретные, заранее описанные операции). "Свободного" эндпоинта для запуска
  произвольного BSL в этом расширении нет и не планируется.
- `create_document` структурно не может провести документ — ни на уровне 1С (жёстко
  `РежимЗаписиДокумента.Запись`), ни на уровне Go-инструмента (в схеме параметров нет поля
  "провести"), ни на уровне подсказки инструмента для LLM.
- Каждая запись аудируется в журнал регистрации 1С (`MCP: ...`).
